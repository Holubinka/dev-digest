# specs/ — repo-wide

Design specifications for work that spans more than one package. Work confined to a
single package belongs in `<module>/specs/`.

**Goes here:** what we are about to build and why, decisions and their alternatives,
acceptance criteria.

**Does not go here:** how the system already works (that is
[`../docs/`](../docs/README.md)), agent conventions (that is
[`../AGENTS.md`](../AGENTS.md)), or post-mortems (that is
[`../INSIGHTS.md`](../INSIGHTS.md)).

Naming: `LNN-topic.md` for course lessons, `NN-topic.md` otherwise.

A spec is finished when someone else could implement it without asking you questions.
Once the work ships, leave the spec as a record — do not rewrite history to match the
implementation; note the divergence instead.
